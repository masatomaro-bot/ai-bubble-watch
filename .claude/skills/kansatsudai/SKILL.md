# 慈愛の観察台 — 日次市場解説

`pipeline/` (このリポジトリ)が毎朝GitHub Actionsで計算・書き込んだテクニカル指標を
Google Driveのスプレッドシートから読み込み、`docs/PIPELINE.md`にある設計思想に沿って
市場解説を生成する。

## 設計上の役割(必ず守ること)

- あなたの役割は「数値の要約」ではなく「マクロ→セクター→銘柄の因果を文章で説明すること」。
  数値を羅列するだけの出力は禁止。なぜその数字になったのか、その日の値動きの理由まで書く。
- チャートの視覚的判断(ローソク足・Darvas Box・サポートライン等)は本人がTradingViewで行う。
  チャート表示やダッシュボード/カード型の見せ方は作らない。プレーンな文章で出力する。
- ファンダメンタルズ(EPS成長率・売上成長率等)はこのスプレッドシートの対象外。
  必要なら一次情報(ニュース検索やSeeking Alpha等)を別途読んで補う。

## 手順

1. **スプレッドシートを探す**: Google Driveで `慈愛の観察台` というタイトルのスプレッドシートを検索し、
   `read_file_content` で中身を読む(`Watchlist_Latest` / `Sector_RS` / `Breadth_History` の3タブ)。
   複数ヒットした場合は最も新しく更新されたものを使う。
2. **鮮度を確認する**: `Watchlist_Latest` の `Date` 列が直近の営業日になっているか確認する。
   数日以上前のままなら、GitHub Actionsが失敗している可能性があるので、その旨を先に伝える
   (黙って古いデータで解説を続けない)。
3. **必要に応じてニュースを補う**: その日の値動きが大きい銘柄(DayChangePctの絶対値が大きい)、
   RS Ratingが高い銘柄、VCPCandidate/TrendTemplatePassがTRUEの銘柄については、
   Web検索で当日のニュース・決算・マクロ環境(FRB、金利、指数の値動き等)を補い、
   因果関係の説明に使う。憶測で書かず、裏付けが取れないことは書かない。
4. **以下の構成で出力する**(この順番・見出しを守る):
   - **L0**: その日のマクロテーマ要約
   - **L1**: 強含んでいるセクター/業種RS(`Sector_RS`タブのRSRating降順)
   - **L2**: 出来高を伴いRSが上抜けてきたリーダー候補銘柄+理由
     (`Holding=FALSE`の観察銘柄が対象。RS Rating・VCPCandidate・TrendTemplatePass・RelVolumeを根拠として使う)
   - **ポートフォリオの現状**: `Holding=TRUE`の実際の保有銘柄のみを対象に、強弱・偏りを説明する
   - **関連ニュース・決算等の特記事項**

## 保有銘柄と観察銘柄の区別(重要)

`Watchlist_Latest`タブの`Holding`列で、実際に保有しているポートフォリオ銘柄(TRUE)と、
まだ保有していない観察のみの銘柄(FALSE)を区別する。**この2つを混同しないこと**:

- 「ポートフォリオの現状」セクションは`Holding=TRUE`の銘柄だけを扱う
  (保有ポジションの評価・強弱・リスクの話)
- 「L2: リーダー候補」セクションは`Holding=FALSE`の銘柄だけを扱う
  (まだ保有していない、新規エントリー候補としての値動き・出来高・RS上抜けの話)
- 保有銘柄がL2的な強い値動きを見せている場合は「ポートフォリオの現状」の中で
  ポジション管理の観点(積み増し/様子見/利確ライン等)として触れる

## 注意

- `Breadth_History` は日々の推移を見る指標なので、直近数行の変化(改善/悪化)にも触れるとよい。
- 全市場スクリーニングではなく、あくまでウォッチリスト内でのRS/Breadthである前提を忘れないこと
  (「市場全体が」ではなく「観察台の中では」という書き方をする)。
- スプレッドシートが見つからない/読み込めない場合は、正直にその旨を伝えて止まる。
  存在しないデータを想像で埋めない。
