1. `market_climate.py` — 地合い(市場全体の状態)を毎日記録する
2. `ffty_screener.py` — FFTY(CapForce IBD 50 ETF)構成銘柄をミネルヴィニ・
   トレンドテンプレートでスクリーニングし、予算内の候補を記録する

VCPやカップ・ウィズ・ハンドルなどベースパターンの視覚判定は行わない。
そこはチャートをTradingViewで自分の目で見て判断する、という方針のまま。
このツールがやるのは「トレンドテンプレートを通過した監視対象」を毎日
機械的にログに残すところまで。

## 1. 何を計算しているか

### market_climate.py (地合い)

オニミネサイトのトップページに書かれている定義をそのまま実装した部分と、
自分で近似した部分がある。

| 項目 | 実装内容 | 出典/根拠 |
|---|---|---|
| 売り抜け日数・失速日数 | NASDAQ総合(^IXIC)・S&P500(^GSPC)、直近25営業日、前日比-0.2%以下+出来高増=売り抜け、+0.2%未満の小幅高+出来高増+安値圏引け=失速、25営業日経過 or +5%ラリーで除外 | オニミネのトップページ注記をそのまま実装 |
| 「安値圏引け」の定義 | 当日レンジの下位25%以内で引けたこと、と独自に定義 | オニミネ側は数値非公開のため独自解釈(要調整) |
| セクター・ローテーション | 11 SPDRセクターETFの相対力を簡易RRG(RS-Ratio/RS-Momentum)で4象限に分類 | 一般的なJdK RRG方式の簡易実装(厳密な計算式とは異なる近似) |
| テーマ・ローテーション | GICS11セクターと重複しない約12のテーマ型/サブセクター型ETF(半導体・クリーンエネ・宇宙防衛・原子力等)を同じRRG方式で分類 | オニミネの「産業セクター月間パフォーマンス」(約15テーマ)に相当。正確な構成銘柄・テーマ数は非公開のため近似 |
| セクター温度感・本日の判定 | 11セクターETFそれぞれを「上昇/買い集め/中立/調整」の4分類(価格の50日線・200日線に対する位置 + 相対力の直近20営業日変化の向き)にし、多数決でRISK-ON/RISK-OFF/MIXEDを判定 | オニミネの「セクター体温の多数決で本日の地合いを判定する」という考え方を再現。**分類の閾値・ロジックは完全に自前設計**であり、オニミネの実際の判定と一致する保証はない |
| 市場の幅(ブレッドス) | 広域ユニバース(iShares IWV/Russell3000ベース、取得失敗時はS&P500にフォールバック)のうち、厳密な新52週高値/安値銘柄数、値上がり/値下がり銘柄数、出来高ブレッド(値上がり銘柄の出来高比率)、52週高値/安値2%以内の比率 | オニミネは全米国株(~4465銘柄)が母集団。母集団は完全一致しないため、**水準はオニミネの数字と直接比較できない** |
| Market Leader(個別銘柄RS) | ブレッドス母集団内でのトレーリング1年リターン百分位を上位から20銘柄 | 本物のIBD RSレーティングとは異なる代替指標(proxy)。ffty_screener.pyと同じ考え方 |
| 指数ステージ | 50/150/200日線に対する位置 | 一般的なステージ分析の考え方 |
| 経済イベントカレンダー | 未実装 | 具体的な発表日を裏付けなく記載しない方針のため、着手を見送り中 |

### ffty_screener.py (FFTY×トレンドテンプレート×予算フィルタ)

1. FFTY(CapForce IBD 50 ETF)の構成銘柄一覧を取得(現金・短期国債などは除外)
2. 各銘柄にミネルヴィニ・トレンドテンプレート8条件のうち7条件を計算
   (価格>150日線>200日線、200日線上昇中、50日線が150/200日線より上、
   価格>50日線、52週安値から+25%以上、52週高値から-25%以内)
3. 8条件目(RSレーティング≧70)は本物のIBD RSレーティングを再現できないため、
   **FFTY構成銘柄"内"でのトレーリング1年リターンの百分位**を代替指標として使用
   (上位30%=70点相当、という近似)
4. 為替(USD/JPY)を取得し、1株あたり価格が予算(30万〜100万円)に収まるかを判定
5. 結果を日付付きでログに残す(合格数の多い順)

## 2. 重要な制約・注意点(読んでから使うこと)

- **FFTY構成銘柄の取得方法**: FFTYは2026年4月にInnovatorからCapForceへ運用移管
  されており、公式サイト(capforceetf.com)にクリーンなCSV/API公開URLが見当たら
  なかった。そのためPlaywright(ヘッドレスブラウザ)で保有銘柄ページを
  レンダリングしてスクレイピングする方式にしている。サイトのHTML構造が
  変わるとセレクタ調整が必要になる、という前提の実装。
- **このリポジトリを作った環境(サンドボックス)は外部ネットワークに出られず**、
  yfinance・capforceetf.com・iShares(universe.py)への実アクセスでの動作確認
  ができていない。ロジック部分は合成データでのユニットテスト(`tests/`)で
  検証済みだが、**実データでの初回実行結果は必ず目視確認すること**。
- 8条件目のRSレーティングはIBD公式値の代替(proxy)であり、本物のRSレーティング
  とは数値の意味が異なる。Market Leaderの`rs_percentile`も同様。
- ブレッドス(市場の幅)は広域ユニバース(iShares IWV/Russell3000ベース)を
  母集団にした近似値。オニミネの表示する数字と桁や水準を直接比較しないこと。
  取得に失敗した場合はS&P500(~500銘柄)に自動フォールバックするため、実行の
  たびに`breadth_universe_source`(sheetの列 / JSON出力)を確認し、想定外に
  `sp500`側へ落ちていないかをチェックすること。
- **`universe.py`のiShares保有銘柄CSV取得URLは、実機検証(2026-09-13)で
  機能しないことを確認済み。** CSVではなくiSharesサイトの通常のHTMLページ
  が返ってくる(サイト側の仕様変更でURL/ID体系が変わったと考えられる)。
  実用上はNASDAQ Trader経由(nasdaqlisted.txt/otherlisted.txt)のフォール
  バックで運用する前提とし、iSharesのURL修正は優先度を下げている。
  NASDAQ Trader経由は同じ実機検証で取得成功を確認済み。
- **数千銘柄のyfinance一括取得は実行時間・レート制限が未検証。** 初回は
  `workflow_dispatch`の`max_breadth_tickers`を500程度に絞って実行時間と
  エラーの有無を確認してから、段階的に上限を緩める運用を推奨する。
- セクター温度感(上昇/買い集め/中立/調整)とRISK-ON/OFF判定の閾値は、
  オニミネの非公開ロジックを推測したものではなく、**完全に自前で設計した
  基準**。数値の意味自体がオニミネと異なる可能性がある前提で見ること。
- テーマ・ローテーション(THEME_ETFS)は代理ETFによる近似であり、オニミネの
  正確な369テーマ分類・約15の大分類とは対応関係が異なる。
- 「安値圏引け」の閾値(レンジ下位25%)はこちらの独自解釈。実際のオニミネの
  判定と細部が食い違う可能性がある。
- 経済イベントカレンダーは未実装(意図的に見送り)。実装時はFOMC/BLS等の
  公式発表日程を都度取得する設計にし、日付を手打ちで書かないこと。

## 3. セットアップ

```bash
pip install -r requirements.txt
python -m playwright install --with-deps chromium
```

テスト(`tests/`)も実行したい場合は代わりに `pip install -r requirements-dev.txt` (pytestも入る)。

### Google Sheetsへの書き込みを使う場合

既存の慈愛の観察台パイプラインと同じ、Googleサービスアカウント方式。

1. Google Cloud ConsoleでサービスアカウントJSONキーを発行
2. 書き込み先のスプレッドシートをそのサービスアカウントのメールアドレスに
   共有(編集者権限)
3. 環境変数(またはGitHub Secrets)に以下を設定
   - `GOOGLE_SERVICE_ACCOUNT_JSON` : サービスアカウントJSONの中身(文字列)
   - `SPREADSHEET_ID` : スプレッドシートのID(URLの `/d/` と `/edit` の間の文字列)

Sheetsの環境変数を設定しなければ、標準出力に結果を表示するだけの動作になる
(お試し実行はこちらでOK)。

### GitHub Actionsでの自動実行

`.github/workflows/technical_practice_daily.yml` を既存リポジトリ
(masatomaro-bot/ai-bubble-watch など)に配置し、Secretsに
`GOOGLE_SERVICE_ACCOUNT_JSON` と `SPREADSHEET_ID` を設定すれば、UTC日〜木
22:00 (JST月〜金 朝7:00、直近のUS取引日の終値を反映)に自動実行される。
手動実行したい場合はActionsタブから `workflow_dispatch` で起動でき、その際
`breadth_universe`(broad/sp500)と`max_breadth_tickers`(母集団の件数上限)
を指定できる。**初回実行は`max_breadth_tickers`を500程度に絞って実行時間と
エラーの有無を確認してから、段階的に上限を緩めることを強く推奨する。**

`market_climate.py`単体を手元/CIで実行する場合、以下の環境変数でも同様に
制御できる(`workflow_dispatch`の入力はこの環境変数に渡されるだけ):
- `BREADTH_UNIVERSE` : `broad`(既定) または `sp500`
- `MAX_BREADTH_TICKERS` : 母集団の件数上限(未設定なら無制限)
