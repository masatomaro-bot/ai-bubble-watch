慈愛の観察台(定点観測)とは別建ての「練習テクニカル」(O'Neil/Minervini/VCP方式の
小さめポジションでの練習トレード)用に、次の2つを毎営業日自動実行するスクリプト。

1. `market_climate.py` — 地合い(市場全体の状態)を毎日記録する
2. `ffty_screener.py` — FFTY(CapForce IBD 50 ETF)構成銘柄をミネルヴィニ・
   トレンドテンプレートでスクリーニングし、予算内の候補を記録する

VCPやカップ・ウィズ・ハンドルなどベースパターンの視覚判定は行わない。
そこはチャートをTradingViewで自分の目で見て判断する、という方針のまま。
このツールがやるのは「トレンドテンプレートを通過した監視対象」を毎日
機械的にログに残すところまで。

## 1. 何を計算しているか

### market_climate.py (地合い)

オニミネサイトのトップページに書かれている定義をそのまま実装した部分と、
自分で近似した部分がある。

| 項目 | 実装内容 | 出典/根拠 |
|---|---|---|
| 売り抜け日数・失速日数 | NASDAQ総合(^IXIC)・S&P500(^GSPC)、直近25営業日、前日比-0.2%以下+出来高増=売り抜け、+0.2%未満の小幅高+出来高増+安値圏引け=失速、25営業日経過 or +5%ラリーで除外 | オニミネのトップページ注記をそのまま実装 |
| 「安値圏引け」の定義 | 当日レンジの下位25%以内で引けたこと、と独自に定義 | オニミネ側は数値非公開のため独自解釈(要調整) |
| セクター・ローテーション | 11 SPDRセクターETFの相対力を簡易RRG(RS-Ratio/RS-Momentum)で4象限に分類 | 一般的なJdK RRG方式の簡易実装(厳密な計算式とは異なる近似) |
| 市場の幅(ブレッドス) | S&P500構成銘柄のうち52週高値/安値の2%以内にいる比率 | オニミネは全米国株(~4465銘柄)が母集団だが、ここではS&P500(~500銘柄)で代替。**水準はオニミネの数字と直接比較できない** |
| 指数ステージ | 50/150/200日線に対する位置 | 一般的なステージ分析の考え方 |

### ffty_screener.py (FFTY×トレンドテンプレート×予算フィルタ)

1. FFTY(CapForce IBD 50 ETF)の構成銘柄一覧を取得(現金・短期国債などは除外)
2. 各銘柄にミネルヴィニ・トレンドテンプレート8条件のうち7条件を計算
   (価格>150日線>200日線、200日線上昇中、50日線が150/200日線より上、
   価格>50日線、52週安値から+25%以上、52週高値から-25%以内)
3. 8条件目(RSレーティング≧70)は本物のIBD RSレーティングを再現できないため、
   **FFTY構成銘柄"内"でのトレーリング1年リターンの百分位**を代替指標として使用
   (上位30%=70点相当、という近似)
4. 為替(USD/JPY)を取得し、1株あたり価格が予算(30万〜100万円)に収まるかを判定
5. 結果を日付付きでログに残す(合格数の多い順)

## 2. 重要な制約・注意点(読んでから使うこと)

- **FFTY構成銘柄の取得方法**: FFTYは2026年4月にInnovatorからCapForceへ運用移管
  されており、公式サイト(capforceetf.com)にクリーンなCSV/API公開URLが見当たら
  なかった。そのためPlaywright(ヘッドレスブラウザ)で保有銘柄ページを
  レンダリングしてスクレイピングする方式にしている。サイトのHTML構造が
  変わるとセレクタ調整が必要になる、という前提の実装。
- **このリポジトリを作った環境(サンドボックス)は外部ネットワークに出られず**、
  yfinanceやcapforceetf.comへの実アクセスでの動作確認ができていない。
  ロジック部分は合成データでのユニットテスト(`tests/`)で検証済みだが、
  **実データでの初回実行結果は必ず目視確認すること**。
- 8条件目のRSレーティングはIBD公式値の代替(proxy)であり、本物のRSレーティング
  とは数値の意味が異なる。
- ブレッドス(市場の幅)はS&P500を母集団にした近似値。オニミネの表示する
  数字と桁や水準を直接比較しないこと。
- 「安値圏引け」の閾値(レンジ下位25%)はこちらの独自解釈。実際のオニミネの
  判定と細部が食い違う可能性がある。

## 3. セットアップ

```bash
pip install -r requirements.txt
python -m playwright install --with-deps chromium
```

テスト(`tests/`)も実行したい場合は代わりに `pip install -r requirements-dev.txt` (pytestも入る)。

### Google Sheetsへの書き込みを使う場合

既存の慈愛の観察台パイプラインと同じ、Googleサービスアカウント方式。

1. Google Cloud ConsoleでサービスアカウントJSONキーを発行
2. 書き込み先のスプレッドシートをそのサービスアカウントのメールアドレスに
   共有(編集者権限)
3. 環境変数(またはGitHub Secrets)に以下を設定
   - `GOOGLE_SERVICE_ACCOUNT_JSON` : サービスアカウントJSONの中身(文字列)
   - `SPREADSHEET_ID` : スプレッドシートのID(URLの `/d/` と `/edit` の間の文字列)

Sheetsの環境変数を設定しなければ、標準出力に結果を表示するだけの動作になる
(お試し実行はこちらでOK)。

### GitHub Actionsでの自動実行

`.github/workflows/technical_practice_daily.yml` を既存リポジトリ
(masatomaro-bot/ai-bubble-watch など)に配置し、Secretsに
`GOOGLE_SERVICE_ACCOUNT_JSON` と `SPREADSHEET_ID` を設定すれば、UTC日〜木
22:00 (JST月〜金 朝7:00、直近のUS取引日の終値を反映)に自動実行される。
手動実行したい場合はActionsタブから `workflow_dispatch` で起動できる。

## 4. ローカルで試す

```bash
python market_climate.py    # 地合いをJSON表示 (+Sheets設定時は書き込みも)
python ffty_screener.py     # FFTY候補一覧を表示 (+Sheets設定時は書き込みも)
python -m pytest tests/ -v  # 計算ロジックの単体テスト(合成データ)
```
